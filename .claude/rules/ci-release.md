# CI, build & phát hành

> Tách từ `AGENTS.md` (1.3.959). Claude Code tự nạp file này khi đọc / sửa file khớp `paths`; agent khác phải tự đọc trước khi sửa phân hệ này.

**CI không phải test gate.** `.github/workflows/build-ipa.yml` chỉ `xcodegen generate` → `xcodebuild archive` (unsigned) → đóng gói IPA + nhồi `espeak-ng-data` → gửi Telegram. Nó **không chạy unit test, không chạy `check_architecture.py`, cũng không truy vấn `codegraph` MCP**, và chỉ trigger khi đổi `Sources/**`, `project.yml` hoặc phần vtts (`Vendor/vtts/**`, `Scripts/ci/check_vtts_assets.sh`, `Scripts/ci/vtts_bridge_smoke.c`, `Scripts/ci/vtts_say_lex_stubs.c` — mục vtts bên dưới). Nghĩa là CI xanh = *biên dịch được*, không phải *đúng*. Trước `xcodegen`, bước Cache/Build AudioCpp dựng `Vendor/AudioCpp/AudioCpp.xcframework` (audio.cpp ghim ở `Scripts/ci/audiocpp_ref.txt` + bản vá `Scripts/ci/audiocpp_patches/`, CPU, không OpenMP/Metal; từ 1.3.924 build kèm ggml-blas = Accelerate cho codec + nạp prompt của Turbo; 1.3.929 thêm pool luồng giữ lâu, 1.3.930 repack trọng số âm học) bằng `Scripts/ci/build_audiocpp_ios.sh`; khoá cache = hash script + tag + bản vá. Workflow riêng `audiocpp-ios.yml` dựng framework + kiểm bản vá trùng mã âm thanh với bản gốc + codec BLAS ≥ 90 dB + pool luồng trùng từng byte + logit repack trong nhiễu q8 — `audiocpp_acoustic_check.py` (`audiocpp_parity_macos.sh`) khi đổi các file đó. Build local cần chạy script này trước `xcodegen` (thư mục `Vendor/AudioCpp/` bị gitignore).

**Chế độ biên dịch Release** (1.3.916): target FreeBook build Release bằng `SWIFT_COMPILATION_MODE: singlefile` và **không** sinh debug info / dSYM (`project.yml` › `settings.configs.Release`; gói SPM giữ mặc định). Lý do: WMO biên dịch cả module trong một tiến trình mất ~1000–1300 s trên runner `macos-15` (3 lõi / 7 GB) — 52% là tối ưu SIL chạy gần như một luồng, RAM ~5 GB nên phải swap; mã Swift tăng 2,5× từ 1/10 tới 13/11 nên càng ngày càng lâu. Đo cặp cùng máy (nhánh thử `exp/ci-timing`): archive 1137–1330 s → 490–620 s. Đánh đổi: mất tối ưu xuyên file (inline / specialize / suy `final`) ⇒ code Swift tính nặng (khử nhiễu STFT, fbank, tách từ VietPhrase, chuẩn hoá chữ) có thể chậm hơn chút — so RTF với bản trước 1.3.916 thì nhớ điều này; ORT / Core ML / audio.cpp không đổi. Runner dùng chung lệch tới ~2× giữa các lượt: so thời gian build thì lấy cửa sổ biên dịch SwiftSoup (không đổi) làm mốc. Đừng bật lại WMO / dSYM nếu anh Bửu không yêu cầu. Hàm type-check chậm nhất còn đó (`ReaderView.readerObserverLayer` ~13 s, chuỗi ~18 modifier) — tách nó chỉ lợi vài phần trăm.

**Version app tự nâng theo CHANGELOG** (1.3.723): bước `Resolve App Version` của `build-ipa.yml` lấy số bản đầu `Docs/CodeGraph/CHANGELOG.md` làm `MARKETING_VERSION` (`CFBundleShortVersionString`) và `github.run_number` làm `CURRENT_PROJECT_VERSION` (`CFBundleVersion`), truyền vào `xcodebuild archive` rồi chốt lại bằng `plutil` trong IPA; caption Telegram có version. CI **không** commit ngược về repo. Bản build tay mang mặc định `1.3.0 (1)` của `project.yml`. Code đọc version qua `AppVersionInfo` (`Sources/Common/Utils/`). Hệ quả: commit quên thêm entry CHANGELOG mới thì version không đổi, chỉ số build tăng.

**Nguồn cập nhật LiveContainer** (1.3.724): lượt build xanh trên `main` chạy `Scripts/ci/publish_altstore_source.py` — tạo GitHub Release `build-<số build>` kèm `TangCongCac-<version>-<số build>.ipa`, giữ **mọi** release `build-*` (1.3.914 bỏ giới hạn 5 — GitHub không giới hạn số release), rồi ghi `apps.json` (chỉ liệt kê 5 bản mới nhất, `--keep 5`) (định dạng nguồn AltStore) + `icon.png` lên nhánh riêng **`source`** (không phải `main` ⇒ không kích hoạt build). URL nguồn cố định `https://raw.githubusercontent.com/buudvh/FreeBook/source/apps.json` — tin Telegram gửi kèm link này (dòng `📲 Nguồn LiveContainer`), **không** gửi link release — trừ khi không gửi được file IPA (mục Telegram bên dưới, 1.3.1045); app không có nút thêm nguồn (bỏ ở 1.3.726). Job có `permissions: contents: write`; bước đăng `continue-on-error` nên lỗi đăng không làm đỏ build. Repo công khai ⇒ IPA trên Release **có** `GOOGLE_CLOUD_TTS_API_KEY` (người dùng chọn giữ khoá). Đừng sửa tay nhánh `source`.

**Tin Telegram + ghi chú release liệt kê mọi commit** (1.3.725): bước `Collect Commit List` lấy SHA lần build xanh trước trên `main` (`gh run list`, cần `actions: read`) rồi gọi API so sánh (`gh api …/compare/<cũ>...<mới>`, vì checkout chỉ có 1 commit) ⇒ `build/commit_subjects.txt`; không lấy được thì chỉ commit cuối. `Scripts/ci/telegram_commit_summary.py` dựng tin và **cắt vừa giới hạn trước khi gửi** (đếm UTF-16: caption 1024, tin 4096; thừa ⇒ "… và K commit khác"; subject trùng chỉ giữ lần đầu, 1.3.729) và ghi chú release đầy đủ. `Scripts/ci/telegram_send.sh` (`tg_call`) coi là đã gửi **chỉ khi** phản hồi có `"ok":true`, lỗi thì thử lại **2 lần**; hết lượt chỉ cảnh báo, không làm đỏ build. Một lượt push mang nhiều commit là bình thường: session con chỉ commit, session chính push gộp một lần.

**IPA lớn hơn giới hạn gửi file của bot** (1.3.1045, anh Bửu: "file realease vượt 50 MB có vấn đề gì ko"): Bot API chỉ nhận file ≤ 50 MiB (52 428 800 byte). Bước "Send IPA to Telegram": IPA dưới ngưỡng ⇒ `sendDocument`; vượt ngưỡng **hoặc** `sendDocument` hết lượt thử vẫn lỗi ⇒ `sendMessage` (cùng danh sách commit, tiêu đề ghi lý do + cỡ IPA) kèm `⬇️ Tải IPA: <RELEASE_IPA_URL>` — link asset của release `build-<số build>`, bước Publish ghi vào `GITHUB_ENV` (không có release — nhánh khác / Publish lỗi ⇒ link trang lượt build, IPA ở Artifacts). Trước đó ngưỡng là 50 000 000 byte và file lớn hơn đẩy lên transfer.sh — dịch vụ đã chết (build 1327: tin tới với link trống), **đừng** dùng lại. Package IPA nén `zip -9`. Từ 1.3.1046 (4 giọng vtts) IPA ~53 MB ⇒ Telegram chỉ nhận tin kèm link, không nhận file.

**Báo có bản mới trong app** (1.3.727): `AppUpdateRepository` (`Services/AppUpdate/`, `@MainActor @Observable`) đọc `apps.json` của nhánh `source` (1.3.760: qua API Contents của GitHub — `AppUpdateSourceClient`, `Accept: application/vnd.github.raw+json`, đệm tối đa 60 s; link `raw.githubusercontent.com` bị CDN giữ bản cũ tới 5 phút và thêm tham số không lách được, nên chỉ còn là đường lùi khi API lỗi / hết 60 lượt mỗi giờ) mỗi lần mở app, khi quay lại app nếu đã quá 30 phút, và khi bấm dòng "Phiên bản ứng dụng" ở Cài đặt (1.3.732; trước đó giãn cách 6 giờ cho mọi lần nên bản ra ngay sau một lần kiểm phải chờ 6 giờ), so **số build** của nguồn với `CFBundleVersion` đang chạy. Hiện ở dải báo tab Kệ sách (`AppUpdateBanner`, không có nút cập nhật — bấm vào mới xem thay đổi), hàng Cài đặt › Thông Tin và chấm đỏ tab Cài Đặt; ẩn/bỏ qua/đã xem nhớ theo số build. Icon `arrow.down.square`, không dùng chuông, không ghi Trung tâm thông báo. **Không** có "Cập nhật ngay": `livecontainer://install` gọi từ app con đang chạy trong LiveContainer chỉ hiện "mở lại LiveContainer để cài"; nút "Mở LiveContainer" dùng `livecontainer://livecontainer-launch?bundle-name=ui` (chưa thử trên máy); trước khi mở, `LiveContainerSwitchPreparer` (1.3.824) dừng TTS / nhạc / phim đang có + tắt `AVAudioSession` + chờ 0,4 s — LiveContainer chuyển app bằng cách xin iOS mở lại chính nó rồi tự `SIGKILL`, đang phát nền thì iOS không mở lại (app chỉ tắt). Nút "?" ngay sau chữ "Phiên bản ứng dụng" (1.3.810, nút anh em đặt chồng — chạm phần còn lại của hàng vẫn kiểm bản mới) ⇒ sheet **"Có gì mới ở bản này"** (`AppReleaseNotesSheet`) của **bản đang chạy**, đọc qua `AppReleaseNotesLoader`: `ReleaseNotes.txt` trong bundle (bước Package IPA của `build-ipa.yml` ghi từ `build/commit_subjects.txt` bằng `telegram_commit_summary.py --format notes`; lỗi / thiếu ⇒ bỏ qua, không đỏ build) → bản cùng `buildVersion` trong `apps.json` (`AppUpdateSourceClient.fetchVersion`, nguồn chỉ giữ 5 bản) → "Không còn ghi chú cho bản này". Bản build tay không có file.

Tài sản commit ở `Vendor/vtts/assets/` (`-text` trong `.gitattributes` ⇒ giữ nguyên byte): `vtts/` = **đúng** 5 file đóng vào app (2 giọng M release `v0.11.0` — từ 1.3.1052: `nu-10` = model v0.9.1 train joint 80k bước, `nam-1` trùng byte v0.4.0 — + 2 giọng tự train `vtts-ngochuyen-m-k4.q8.vtts` — 1.3.1044 — và `vtts-googledich-m-k4.q8.vtts` — 1.3.1046 —, SHA256 ở `LOCAL_SHA256SUMS`, CC BY-NC 4.0 — + từ điển VLEX `lex_en.bin`; folder resource ⇒ `FreeBook.app/vtts/`), `extra/` = bản S dự trữ, `cmudict/cmudict.dict` (nguồn dựng VLEX), `SHA256SUMS` (4 dòng vi-en nguyên văn của release) + `LOCAL_SHA256SUMS`. `Vendor/vtts/tools/` = công cụ upstream cùng commit (`build_lexicon.py` + module Python nó cần, `vtts_say.c`, `Makefile`); `Vendor/vtts/rebuild_lex_en.sh` dựng lại `lex_en.bin` không mạng (Python ≥ 3.11, ~8 phút, `--write` để ghi đè).
