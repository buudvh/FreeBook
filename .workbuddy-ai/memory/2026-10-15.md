## Giải mã `script_data` (Vbook AES-256-CBC) — ngoài phạm vi FreeBook

User dán một JSON `script_data` gồm 10 file `.js` bị mã hoá và nhờ decode.

**Nhận dạng scheme**: token `x0P1Xx`→`+`, `x0P2Xx`→`/`, `x0P3Xx`→`=` (đúng 3 token, mỗi token thay 1 ký tự — kiểm chứng bằng `len - 5*count ≡ 0 (mod 4)` trên cả 10 file) ⇒ phần còn lại là **Base64 của AES-256-CBC**.

**Suy luận từ dữ liệu thuần (không cần key)**: mọi payload có độ dài chia hết cho 16, và các tiền tố chung giữa các file rơi đúng vào bội số 16 byte (16/32/80/256) ⇒ block cipher 16 byte + padding PKCS#7.

**Công thức key (Vbook)**:
```
payload = "com.vbook.app" + metadata.source + metadata.author
aesKey  = SHA256( MD5(payload) dạng hex string )   # 32 byte
IV      = 16 byte 0
```
Nguồn: `kychitoge/vbook-ext` → `docs/SOURCE_OBFUSCATION_GUIDE.md`, `tools/encrypt/encrypt.js`, `tools/cli/vbook_decoder.js`.

**Điểm mấu chốt**: **không thể decode chỉ từ ciphertext** — key phụ thuộc `source` + `author` trong `plugin.json` của extension, hai trường này không có trong `script_data`.

**Kết quả**: bộ 10 file khớp 100% với extension `hhtqvietsub` v10 trong `Darkrai9x/vbook-extensions` (so khớp chuỗi ciphertext trùng khít) ⇒ `source=https://hh3d.boats`, `author=vBook`. Key dùng được:
`SHA256(MD5("com.vbook.apphttps://hh3d.boatsvBook"))` = `d476a9f7af052a90c72d1c1bd6f4e2ac27977369466ebcdbb01ff8e1c8292073`.

Đã giải mã ra 10 file JS sạch (không nén), ghi vào `hhtqvietsub_decoded/` ở root workspace.

**Lưu ý tái sử dụng**: khi gặp chuỗi có `x0P1Xx/x0P2Xx/x0P3Xx` → đây là extension Vbook; phải tìm `plugin.json` (source+author) trước, sau đó mới derive key. Đối chiếu ciphertext với các repo extension công khai là cách nhanh nhất để lấy metadata.
